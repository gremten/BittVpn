# Матрица состояний из флоу (создать или проверить)

Порядок проекта (ЖР §83, §124): джобы → сценарии → гипотезы → флоу → **карта экранов (матрица «экран × состояния»)** → экраны со всеми состояниями → спецификация. Пиши «пользователь». Читай `references/` по шагам. Figma сам не читай и не меняй: рисует сессия Дизайн, ты даёшь чистый текст и связку. Названия «Карта экранов» / «Спецификация экранов» — предложение, не из источников.

## Режим 1. Создать матрицу

**Вход.** Нужны флоу (свежая версия автора) и сценарий. **Нет флоу или сценария — стоп: «сначала флоу / сценарий».** Затем задай автору пронумерованные вопросы В1–В9 (`references/state_matrix_criteria.md`, раздел 4): какие экраны, какие общие, где макеты, какие решения записаны, куда «назад», что приходит с сервера, названия, кому передавать, формат вывода. Пока ответов нет, не придумывай: «Нет → Дизайн» и вопрос.

**Работа.**
1. Экраны = квадраты флоу, колонки по главной линии слева направо; шит над экраном — вторым рядом (М2).
2. Состояния собирай из сценария, журнала, гипотез, макетов; общий экран описывай один раз с «Откуда» и словом «Общий» (М1, М5).
3. Карточка — четыре поля: состояние, видит, → куда, статус (М3). Шапка: название и «Откуда» (М4). «Назад» = туда, откуда пришёл (М8).
4. Статусы: Есть / Частично / Нет → Дизайн / Решено → Дизайн / Правило (М9). Для заказа и т. п. — список «статус → экран.состояние», без графа (М10).
5. Стрелки только основной путь вперёд между соседними колонками, подпись — действие из флоу; ветки, возвраты, выходы, «назад» — текстом в карточке (М6).
6. Цикл пропусков: некуда положить → экран/правка флоу; своя цель → экран (оговорка: один экран в продукте); кусок экрана → состояние; слишком много → делить; действие вне флоу → правка флоу (М12). Базовые состояния — проверка (М11).
7. Очисти язык: слова автора, без кодов, ID, номеров, префиксов «Основание / Макет / Не хватает», цен, придуманных текстов (М7). Связка отдельно (М13).
8. Проверка М1–М14, «было → стало», повторная проверка; показать автору целиком.

**Результаты.** Чистый файл карточек и стрелок (образец `references/screen_map_cards_clean.md`); связка; находки; вопросы автору и разработчику (до 10); оценка и вердикт.

## Режим 2. Аудит существующей матрицы

Сначала вопросы автору Ав1–Ав6 (раздел 5 критериев): свежая версия автора главнее, что правил руками и менять нельзя, флоу и сценарий для сверки, решения, что не открывали. Затем М1–М14 по каждому критерию: ок / частично / нет / не проверено, цикл пропусков, «было → стало». Оценка без накрутки: считаются только «ок», «частично» не «ок», «не проверено» отдельно; блокирующие М1, М6, М7; вердикт оставить / доработать / переделать, границы мои, автором не утверждены.

## Постоянные решения автора (закрыты, не спрашивать)
- Отдельной тех. карты нет; граф состояний заказа не рисуем; «вход» — строка «Откуда», не поле карточки (§124–§126).
- Отказ платёжки и истёкший срок = «Отменён»; состояние называется «Время на оплату вышло»; причину отказа приложение не показывает (§120, §123).
- Шрифты проекта (Martian, стили файла), не Inter (§125).

## Чего не делать
- Не придумывать тексты интерфейса, цены, числа, названия, источники; «Нет → Дизайн» вместо догадки.
- Не рисовать стрелки «назад», ветки и выходы между колонками; не писать в карточке коды и префиксы.
- Не менять гипотезы, сценарий и флоу; правку флоу только предлагать списком.
- Figma — только через Дизайн. Оценка ИИ без автора не утверждена; что не открывал — «не проверено».
