# Матрица состояний из флоу (создать или проверить)

Порядок проекта (ЖР §83, §124): джобы → сценарии → гипотезы → флоу → **карта экранов (матрица «экран × состояния»)** → экраны со всеми состояниями → спецификация. Пиши «пользователь». Читай `references/` по шагам. Figma сам не читай и не меняй: рисует сессия Дизайн, ты даёшь чистый текст и связку. Названия «Карта экранов» / «Спецификация экранов» — предложение, не из источников.

## Режим 1. Создать матрицу

**Вход.** Нужны флоу (свежая версия автора) и сценарий. **Нет флоу или сценария — стоп: «сначала флоу / сценарий».** Затем задай автору пронумерованные вопросы В1–В9 (`references/state_matrix_criteria.md`, раздел 4): какие экраны, какие общие, где макеты, какие решения записаны, куда «назад», что приходит с сервера, названия, кому передавать, формат вывода. Пока ответов нет, не придумывай: «Нет → Дизайн» и вопрос.

**Работа.**
1. Колонки по главной линии флоу слева направо; каждый экран, даже с одним состоянием (Приветствие), — своя колонка; один экран продукта — одна колонка: шит над экраном и состояние с другим наполнением — карточки той же колонки, квадраты флоу одного экрана сливаются на карте, флоу не меняется (М2, М3); без решения автора не сливать, а спросить.
2. Состояния собирай из сценария, журнала, гипотез, макетов; общий экран описывай один раз с «Откуда» и словом «Общий» (М1, М8).
3. Карточка на макете — три поля: состояние, видит, → куда (М4); статус словами не пишется. Название — понятное состояние, у основного название экрана, не «Основной» (М5). «→» — одна короткая строка: куда ведёт главное действие (happy path), без «тот же экран», ветвлений, «;» и «назад — …»; если действие остаётся на экране, строки нет; особое «Назад: …» — отдельной строкой и только решённое автором (М6, М11). Шапка: название и короткая «Откуда» или без неё (М7).
4. Статус каждой карточки (Есть / Частично / Нет → Дизайн / Решено → Дизайн / Правило) остаётся в чистом файле как данные для значка из приложения: Есть — галочка (зелёный); Нет → Дизайн и Решено → Дизайн — крестик (красный); Частично — «в работе» (жёлтый); Правило — без значка (ЖР §128, М12). Для заказа и т. п. — список «статус → экран.состояние», без графа (М14).
5. Стрелки только основной путь вперёд между соседними колонками, подпись — действие из флоу; ветки, возвраты, выходы, «назад» — на карте не показываются (М9).
6. Цикл пропусков: некуда положить → экран/правка флоу; своя цель → экран (оговорка: один экран продукта — одна колонка); кусок экрана или другое наполнение → карточка той же колонки; слишком много → делить; действие вне флоу → правка флоу (М16). Базовые состояния — проверка (М15).
7. Очисти язык: слова автора, без кодов, ID, номеров, префиксов «Основание / Макет / Не хватает», цен, придуманных текстов (М10). Связка отдельно (М17).
8. Проверка М1–М18, «было → стало», повторная проверка; показать автору целиком.

**Результаты.** Чистый файл карточек и стрелок (образец `references/screen_map_cards_clean.md`); связка; находки; вопросы автору и разработчику (до 10); оценка и вердикт.

## Режим 2. Аудит существующей матрицы

Сначала вопросы автору Ав1–Ав6 (раздел 5 критериев): свежая версия автора главнее, что правил руками и менять нельзя, флоу и сценарий для сверки, решения, что не открывали. Затем М1–М18 по каждому критерию: ок / частично / нет / не проверено, цикл пропусков, «было → стало». Оценка без накрутки: считаются только «ок», «частично» не «ок», «не проверено» отдельно; блокирующие М1, М3, М4, М5, М6, М9, М10; вердикт оставить / доработать / переделать, границы мои, автором не утверждены.

## Постоянные решения автора (закрыты, не спрашивать)
- Отдельной тех. карты нет; граф состояний заказа не рисуем; «вход» — строка «Откуда», не поле карточки (§124–§126).
- Отказ платёжки и истёкший срок = «Отменён»; состояние называется «Время на оплату вышло»; причину отказа приложение не показывает (§120, §123).
- Шрифты проекта (Martian, стили файла), не Inter (§125). Оформление: фрейм (не секция), заголовок, под ним легенда (значок + цвет + значение), колонки через 32 px; тёмная тема — фон bg/page, карточки bg/surface, текст токенами; цветных заливок карточек нет (§127, М13).

## Чего не делать
- Не придумывать тексты интерфейса, цены, числа, названия, источники; «Нет → Дизайн» вместо догадки.
- Не писать строку статуса на карточке и обычное «назад» в строке «→»; не размазывать один экран по нескольким колонкам; не писать «Основной» вместо названия, «тот же экран», ветвления в «→»; не рисовать стрелки «назад», ветки и выходы между колонками; не писать в карточке коды и префиксы.
- Не менять гипотезы, сценарий и флоу; правку флоу только предлагать списком.
- Figma — только через Дизайн. Оценка ИИ без автора не утверждена; что не открывал — «не проверено».
