# Сценарий из джобов (создать или проверить)

Порядок проекта (ЖР §83): джобы → сценарии → гипотезы → флоу. Пиши «пользователь», не «человек». Читай справочные файлы по шагам, не все сразу. Все файлы в `references/`.

## Режим 1. Создать сценарий

**Вход (до работы).**
1. Нужны джобы (Core, T, O, R). **Нет джобов — стоп, скажи автору «сначала джобы».** Сценарий не создаётся.
2. Задай автору вопросы на вводные: П1–П10 плюс вопросы из темы и джобов. Вопросы выписаны полностью, пронумерованы, автор отвечает по номерам. Читай: `references/scenario_creation_guide.md`, разделы 0, 1а, 3.
3. Пока обязательные вопросы без ответа, ничего не придумывай, помечай «не решено».

**Работа (7 шагов).**
1. Сборка по образцу: `references/onboarding_scenarios_for_reading_v5.md`, формат `references/scenario_template.md`. Только контекст пользователя: боль, ожидание, ставка. Без экранов, механики, решений продукта, цифр.
2. Роли по знаниям, задачам, трудностям, отдельно от обстоятельств (гайд, раздел 2, шаг 2).
3. Подсценарии: плоские, событийные, 2–4 предложения, без ролей и задач внутри; у каждого источник (джоб / автор / «ИИ, не проверено»).
4. Аудит 1 по Бирману: режим 2.
5. Исправление «было → стало» по каждой проблеме (гайд, раздел 7).
6. Валидация у автора: покажи в чате всё целиком, подсценарий → джоб → гипотеза или «не решено»; автор подтверждает «наша ли ситуация». Проверка на реальных пользователях — необязательно, позже.
7. Аудит полноты (гайд, раздел 0, шаг 7): покрыты ли все джобы и группы ситуаций, у каждого подсценария связь, нет сирот.

**Результаты.** Сценарий и подсценарии в формате v5 (поля 1–4); связка отдельно (из джоба / источник / решение или «не решено» / покрывает); аудит 2 (финальный) с оценкой и вердиктом; список оставшегося «не решено» вопросами автору.

## Режим 2. Аудит существующей фичи

Читай `references/universal_scenario_audit.md`. Сначала вводные автору (раздел 0, Ав1–Ав10): текст фичи, более свежая версия автора (она главнее репозитория), джобы, что согласовано и не правится, что автор правил руками. Затем: кор К1–К9 (К9 — учёт джобов и источников, блокирующий: каждая ситуация выходит из джоба или помечена «автор», каждый джоб учтён; в отчёте таблица «учтено / не учтено» по обоим направлениям); 30 вопросов А1–Е10; проверки У1–У12; оценка по шкале 10 с разбивкой; вердикт (оставить / доработать / переделать; границы мои, автором не утверждены); исправление «было → стало» (боль, ожидание, ставка вместо решения; убранное уходит в связку); повторный аудит. Если версия автора нарушает аудит, не правь её, а перечисли расхождения с причиной. В итоговой оценке отдельной строкой «сверка с эталоном» (раздел ниже): не блокирует, в счёт не входит.

## Общий список ролей продукта (решение автора, 2026-11-15)
Роли живут в общем списке `references/product_roles.md` (копия `research/product_roles.md`), источник «автор». Блок «Роли» остаётся внутри каждого сценария, но показывает только роли из общего списка, дословно (формулировка одна и та же везде); своих ролей сценарий не вводит; повтор роли в разных сценариях норма (критерий А5). Расхождение формулировки между сценариями (например, у «Нового пользователя») — пока не ошибка: автор оставил как есть, обе версии зафиксированы в списке с пометкой «ждёт слова автора»; в отчёте отметь «частично» по А5, не блокирует, к вопросу не возвращайся сам. Список живёт только в репозитории, в Figma его нет; роль в сценарии показывается названием и формулировкой, без ссылок. Тест «роль / опция» к «Релоканту» не применяй. Роль вне списка — только по слову автора: сначала добавить в список. В отчёте аудита показывай «роли из списка: использованы / не использованы» и новые роли отдельной строкой. Число ролей не требуем, «три роли» не норма. Где список лежит в Figma, решает автор.

**Подсказка, не критерий (ждёт слова автора, автор её не утверждал):** граница «роль / опция» — роль устойчиво меняет задачи, права, знания или трудности пользователя; опция выбирается в ситуации и доступна любой роли. Показывай одной строкой «к сведению»; ничего не блокирует и не входит в счёт. Основание и оговорки: `research/roles_birman.md`, раздел 5.

## Принцип: эталон = структура, а не содержание (решение автора, 2026-11-15)
Эталон сценария задаёт структуру записи (поля, порядок, форму подсценария, блок «Связанные сценарии»). Он не задаёт те же роли, то же число ролей, подсценариев или пунктов, те же формулировки. Не требуй от другой фичи ролей и подсценариев онбординга и не снижай оценку за отличие числа и состава; сверяй только форму. Роль — устойчивое различие по знаниям и трудностям; опция любой роли («покупает для близких», «много устройств») отдельной ролью не считается.

## Эталон оформления в Figma (ЖР §137, §138)
Эталон оформления в Figma (файл-копия «BittVPN (Copy)», `lR9XZ0BCDldavxSaTOilwE`, узлы 7685:2 (джобы, вход), 8042:1688 (сценарий)): сверяйся с ним перед созданием и при аудите — структура, поля, шрифты и стили, цвета, паттерны автора. Если контекст другой (другая фича, другой тип, расхождение с эталоном по сути), не копируй вслепую, а задай вопрос автору. Описание узлов: `references/etalon_figma_copy_nodes.md` (ЖР §137, §138). В аудите — отдельная строка «сверка с эталоном»: ок / частично / нет / не проверено; не блокирует и в итоговый счёт не входит.

**Правила оформления эталона** (только подтверждено описанием Дизайна):
- Джобы 7685:2 «Онбординг / первый вход»: FRAME 512×1504; заголовок «Первый вход» и блоки Core, Trigger, Outcome, Risk-Reduction; Core — одна фраза «Когда я впервые открываю VPN, я хочу…», Trigger — список «Когда …», Outcome — список «Я хочу …», Risk-Reduction — список «Я не хочу …»; статусы и номера не выводятся.
- Сценарий 8042:1688 «Сценарий / Онбординг»: FRAME 2416×1180, корневой фрейм «Группы», auto-layout везде, инстансов и стрелок нет — связи текстом. Блоки: заголовок; «Первое подключение» с полями Название / Роли (три роли) / Задача / Ход событий; «Подсценарии» — заголовок и абзац в плашке на каждый; «Связанные сценарии» («Оплатил», «Подключил устройство») ссылками-текстами.
- Шрифты и стили: заголовки Martian Grotesk Std Rg 20 (title/medium), метки Golos UI Medium 16 (body/m-medium), текст Golos UI Regular 16 (body/m). Заливки: плашки #f3f3f3, элементы #ffffff.
- **Источник истины — Figma-копия (ЖР §139):** в узле 7 подсценариев (тексты, порядок, роли, задача и ход событий сверены с v5 по `references/etalon_figma_copy_texts.md`; отличие — в Figma нет точки в конце абзацев и ролей); нижний блок называется «Связанные сценарии».

## Чего не делать
- Не создавать сценарий без джобов; не придумывать пороги, сроки, числа, цитаты, источники.
- Не менять гипотезы; не трогать Figma без слова автора; не менять порядок §83.
- Не затирать то, что автор правил руками.
- Оценка ИИ без автора не утверждена; что не открывал — «не проверено».
