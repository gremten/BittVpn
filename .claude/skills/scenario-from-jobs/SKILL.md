# Сценарий из джобов (создать или проверить)

Порядок проекта (ЖР §83): джобы → сценарии → гипотезы → флоу. Пиши «пользователь», не «человек». Читай справочные файлы по шагам, не все сразу. Все файлы в `references/`.

## Режим 1. Создать сценарий

**Вход (до работы).**
1. Нужны джобы (Core, T, O, R). **Нет джобов — стоп, скажи автору «сначала джобы».** Сценарий не создаётся.
2. Задай автору вопросы на вводные: П1–П10 плюс вопросы из темы и джобов. Вопросы выписаны полностью, пронумерованы, автор отвечает по номерам. Читай: `references/scenario_creation_guide.md`, разделы 0, 1а, 3.
3. Пока обязательные вопросы без ответа, ничего не придумывай, помечай «не решено».

**Работа (7 шагов).**
1. Сборка по образцу: `references/onboarding_scenarios_for_reading_v5.md`, формат `references/scenario_template.md`. Только контекст пользователя: боль, ожидание, ставка. Без экранов, механики, решений продукта, цифр.
2. Роли по знаниям, задачам, трудностям, отдельно от обстоятельств (гайд, раздел 2, шаг 2).
3. Подсценарии: плоские, событийные, 2–4 предложения, без ролей и задач внутри; у каждого источник (джоб / автор / «ИИ, не проверено»).
4. Аудит 1 по Бирману: режим 2.
5. Исправление «было → стало» по каждой проблеме (гайд, раздел 7).
6. Валидация у автора: покажи в чате всё целиком, подсценарий → джоб → гипотеза или «не решено»; автор подтверждает «наша ли ситуация». Проверка на реальных пользователях — необязательно, позже.
7. Аудит полноты (гайд, раздел 0, шаг 7): покрыты ли все джобы и группы ситуаций, у каждого подсценария связь, нет сирот.

**Результаты.** Сценарий и подсценарии в формате v5 (поля 1–4); связка отдельно (из джоба / источник / решение или «не решено» / покрывает); аудит 2 (финальный) с оценкой и вердиктом; список оставшегося «не решено» вопросами автору.

## Режим 2. Аудит существующей фичи

Читай `references/universal_scenario_audit.md`. Сначала вводные автору (раздел 0, Ав1–Ав10): текст фичи, более свежая версия автора (она главнее репозитория), джобы, что согласовано и не правится, что автор правил руками. Затем: кор К1–К8; 30 вопросов А1–Е10; проверки У1–У12; оценка по шкале 10 с разбивкой; вердикт (оставить / доработать / переделать; границы мои, автором не утверждены); исправление «было → стало» (боль, ожидание, ставка вместо решения; убранное уходит в связку); повторный аудит. Если версия автора нарушает аудит, не правь её, а перечисли расхождения с причиной.

## Чего не делать
- Не создавать сценарий без джобов; не придумывать пороги, сроки, числа, цитаты, источники.
- Не менять гипотезы; не трогать Figma без слова автора; не менять порядок §83.
- Не затирать то, что автор правил руками.
- Оценка ИИ без автора не утверждена; что не открывал — «не проверено».
