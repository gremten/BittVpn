# Джобы из вводных автора (создать или проверить)

Порядок проекта (ЖР §83): **джобы** → сценарии → гипотезы → флоу → карта состояний. Пиши «пользователь» в своих пояснениях; сами джобы написаны от первого лица («я»). Читай `references/` по шагам, не всё сразу. Критерии и откуда они взяты — `references/jobs_criteria.md`; эталон — `references/etalon_jobs.md` и `references/etalon_figma_copy_nodes.md`.

**Главное правило.** Формулировки джобов принадлежат автору. Ты не придумываешь строки и не правишь эталон. Предложения «было → стало» даёшь списком с причиной и источником, помечая «предложение, ждёт слова автора». Критерии, которых нет в правках автора, помечены «предложено, ждёт слова автора»; блокирующими они не считаются.

## Режим 1. Создать джобы

**Вход (до работы).**
1. Узнай у автора, для какой фичи или области джобы (один Core — одна карточка). Другая фича, не онбординг — в эталон не копируй вслепую, задай вопрос (В6 в `jobs_criteria.md`).
2. Выпиши пронумерованные вопросы, автор отвечает по номерам: какая ситуация (первое открытие, повторное, оплата…); кто человек и что он хочет получить в итоге; из каких ситуаций он приходит (каналы, поломки, поездки); какие результаты нужны; чего человек боится; что есть в продукте сейчас, а чего нет; что автор уже убирал или правил руками; свежая версия автора в Figma (она главнее репозитория); есть ли данные поддержки или интервью. Пока ответов нет — ничего не придумывай, пиши «не решено».
3. Сырьё берёшь только из слов автора, журнала, данных. Строки без источника — «ИИ, не проверено», в сценарий и гипотезы они не идут.

**Работа.**
1. Разложи вводные по четырём блокам: Core — одна работа с результатом; Trigger — ситуации «Когда…»; Outcome — результаты «Я хочу…»; Risk-Reduction — страхи «Я не хочу…» (Д2–Д7).
2. Оформи в формате эталона: заголовок и четыре блока, одна фраза Core, списки, без точек, без номеров и статусов (Д1, Д16). Если автор дал свой текст — не переписывай, только расставь по блокам и отметь расхождения с критериями.
3. Если нужна формулировка, которой у автора нет, дай как «предложение ИИ, ждёт слова автора» рядом с пометкой, из чего она выведена; в итоговый текст она не вставляется без слова автора.
4. Проверь по режиму 2 (Д1–Д20), покажи «было → стало».
5. Покажи автору всё целиком: строка → источник → код (Core, T1…, O1…, R1…) → критерий. Автор подтверждает «наша ли это ситуация» (Д11).
6. Коды = порядок строк (Д10): после правки напомни проверить «Из джобов» в гипотезах.

**Результаты.** Карточка джобов в формате эталона; связка (строка → источник → код); результат проверки Д1–Д20 с оценкой; список «не решено» вопросами автору.

## Режим 2. Проверить существующие джобы

**Вход.** Вопросы автору Ав1–Ав6, по номерам: 1) текст джобов (свежая версия автора из Figma главнее репозитория); 2) что уже согласовано и не правится; 3) что автор правил руками; 4) какие гипотезы и сценарии ссылаются на эти джобы (для Д10, Д19); 5) что есть в продукте сейчас (`research/product_inventory.md` или слова автора) для Д8; 6) что ты не открывала. Если автор не отвечает — «не проверено».

**Проход.**
1. Д1–Д20 по каждой строке: ок / частично / нет / не проверено. Блокирующие — Д1–Д11; неблокирующие — Д12–Д20 (`references/jobs_criteria.md`, раздел 3). Каждому «нет» и «частично» — цитата строки и причина с источником критерия.
2. Список «было → стало → почему» с источником, помеченный «предложение, ждёт слова автора». Формулировку не вписывай в файл автора сама.
3. Если версия автора нарушает критерий, не правь её: перечисли расхождение с причиной и спроси (вопросы В1–В7 в `jobs_criteria.md` уже собраны: не задавай их повторно, если на них уже есть ответ).
4. Повторный проход по затронутым критериям после согласованных правок.

**Оценка.** Считаются только «ок»; «частично» — не «ок»; «не проверено» — отдельной строкой. Отдельной строкой «сверка с эталоном» (ок / частично / нет / не проверено): не блокирует и в счёт не входит. Вердикт: оставить / доработать / переделать; границы мои, автором не утверждены. «Переделать» — не выполнен Д2, Д4 или Д5; ошибку джоба обычно исправляют до сценария и гипотез.

Источник истины — Figma-копия: репозиторий приводится к ней. Описание узла: `references/etalon_figma_copy_nodes.md`; тексты: `references/etalon_jobs.md`. ## Чего не делать
- Не писать строки джобов от себя без пометки; не придумывать источники, числа, цитаты.
- Не вносить в журнал решений (`CASE_DECISION_LOG.md`): решения фиксирует автор.
- Не возвращать убранное автором и не затирать его правки (Д9).
- Не менять эталон и Figma; не переставлять строки, не предупредив о кодах (Д10).
- Не отвечать общими словами «нужно уточнить»: назови строку, критерий, источник, вопрос.
- Не считать критерии «предложено» блокирующими: пока автор не сказал слово, они только вопросы.
