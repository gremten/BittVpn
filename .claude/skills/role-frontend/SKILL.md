# Верстка

## Перед работой

- Прочитай правила проекта (`AGENTS.md` / `CLAUDE.md`) и доки рядом с компонентами, которые тронешь.
- Верстаешь **только то, что утвердил Дизайн/автор**: узлы Figma, на которые есть явное «утверждено». Неутверждённое — вопрос Ядрышку (или автору, если Ядрышка нет).
- Перед `get_design_context` загрузи скилл `figma-design-to-code`.

## Правила

- Переиспользуй существующие компоненты и токены. Не создавай экранные клоны базовых компонентов.
- Геометрия, отступы, типографика — точно по узлу Figma, без «улучшений».
- Ассеты — только локальные файлы в репозитории, никогда временные URL Figma/MCP.
- Обновляй документацию проекта в том же изменении, если правила проекта этого требуют.

## Сервер

- Dev-сервер запускай один раз и держи живым (отдельная вкладка терминала / фоновый процесс), не выключай между правками.
- В облаке: фоновый процесс в контейнере, проверка через Playwright-скриншоты.

## Проверка перед отчётом

- Сборка/линт/тесты проекта проходят.
- Изменённые экраны и переходы проверены в отрендеренном приложении, на мобильной ширине.
- Скриншот рядом с макетом — расхождения названы явно.

## Связь

Вопросы и отчёты — Ядрышку, не напрямую в другие сессии. Коммить и пушь свою работу — незапушенное в облаке пропадает.
