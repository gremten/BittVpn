## Вывод (кратко)

1. **Матрица работает как ловушка пропусков:** на 9 экранах (≈40 карточек) она нашла 11 мест, где решения нет или они расходятся, из них 6 — действительно новые (не видны ни во флоу, ни в сценарии). Главная находка: между «вернулся из платёжки» и «Выбор целей» нет состояния (Н1), а «Время вышло» не имеет макета и спорит с зацикленным таймером прототипа (Н2).
2. **Что дала именно матрица, а не флоу:** расхождение имён (макеты «Ошибка платежа», «Платеж просрочен» ↔ решение «Отменён», «Время вышло»), два возможных «дома» у предупреждения о техработах, отсутствие «Пропустить» на подборе, пустой результат рекомендации.
3. **Критерии из схемы автора сработали неравномерно:** «некуда положить» и «состояние требует действия, которого нет во флоу» ловят пропуски; «кусок экрана → состояние» работает (шиты); «слишком много состояний → делить» не потребовалось (у «Статуса заказа» 6 состояний, делить не нужно, достаточно групп). «Своя цель и действия → отдельный экран» дал спорный результат там, где продукт имеет один экран, а флоу рисует два квадрата (Н3, Н4).
4. **Чего матрице не хватило:** (а) строка «откуда приходят» оказалась обязательной: для 5 из 9 экранов вход определяет «Назад» и видимые части; (б) карточка «состояние» не умеет описывать *момент перехода* (то, что происходит между экранами: возврат из платёжки, проверка итога); (в) готовность макета «есть» часто относится к макету *другого экрана*, на котором состояние уже нарисовано (История), а не к макету онбординга.
5. **Статусы заказа:** отдельный список нужен только как короткая таблица «статус → экран.состояние» (раздел 3); без него «Отменён» двоится.
6. **Вопросов 10** (5 автору, 5 разработчику), раздел 5. Пилот сделан за один проход; второй проход после ответов даст проверку «матрица → правка → матрица» (не выполнялся).

## 1. Колонки-карточки

Экраны сегмента «Выбор целей → оформление и оплата → Статус заказа → Устройство создано» взяты из квадратов флоу (9 колонок): Выбор целей · Рекомендация страны · Детали страны · Детали заказа · Статус заказа · Подтверждение отмены · Оплата прошла · Устройство создано · Купленная страна. «Общий» — экран используется вне онбординга; тогда указано «откуда приходят».

Готовность макета: **есть** (узел назван в проекте), **частично**, **нет**, **не определено** (вводных нет), **решено** (решение автора есть, макета нет).

Поля карточки: **Состояние** · **Что видит** · **→ Куда ведёт** · **Основание** · **Макет** · **Не хватает / у кого**.

### 1.1. Выбор целей (общий: откуда приходят)

Откуда приходят: Приветствие («начинает подбор»); Подтверждение отмены (подтвердил); ◇ «Чем закончилась оплата?» («не прошла или время вышло: возвращается к подбору»); аварийный возврат при истёкшем заказе (ЖР §71 п. 7). «Назад»: из онбординга — туда, откуда пришёл; при входе из возврата после отмены — не определено (Н10).

## 2. Находки

Тип: **НЭ** — нужен новый экран/слот; **ДЭ** — деление экрана; **ПФ** — правка флоу; **С** — состояние, которому нужно только решение/макет; **Вопрос** — ответа в вводных нет.

| № | Находка | Критерий, который сработал | Тип |
|---|---|---|---|
| Н1 | Отказ платёжки: «без отдельного статуса, возврат к подбору». ## 4. Что показал пилот про сам процесс

- Порядок «флоу → список экранов → матрица» сработал: список экранов взят из квадратов без изменений.
- Поля карточки: «основание» и «макет» обязательны (позволяют отличить «решено» от «придумано»); поле «не хватает / у кого» выявило владельцев вопросов (автор / Дизайн / разработчик).
- Нехватает поля **«момент»** (переход между экранами) — Н1 не умещается в карточку состояния; предложение (моё): отдельная строка-карточка «переход» между колонками, как в wireflow.
- Нехватает поля **«вход»** у каждой карточки там, где один экран показывает разное в зависимости от входа (Н14); сейчас оно в заголовке колонки.
- Проверка «матрица → правка → матрица» (раздел 6.7 `tech_map_validity.md`) не проводилась: правок не вносилось, второго прохода нет.
