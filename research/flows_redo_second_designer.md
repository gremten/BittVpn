## 3. Работа: флоу «Выпуск конфига» (версия 3)

**Колонки слева направо.** SQUARE — экран; DIAMOND — решение; ELLIPSE-флоу — ссылка на смежный флоу; ELLIPSE-круг — «Конец». Подписи — действия пользователя, развилки «исход: действие» по форме v2.

### 3.1. Узлы (19)
- колонка 1: ELLIPSE «Флоу «Покупка доступа»» (вход) над SQUARE «Оплата прошла»; под ним SQUARE «Главная»
- колонка 2: SQUARE «Страна»; над ним DIAMOND «Как заменяет устройство?» с ELLIPSE «Флоу «Удаление устройств»» и ELLIPSE «Флоу «Перевыпуск конфигурации»»
- колонка 3: DIAMOND «Есть свободное место?»; над ним DIAMOND «Что делать с местом?» с ELLIPSE «Флоу «Доп. слоты»» и ELLIPSE-кругом «Конец»
- колонка 4: SQUARE «Выбор платформы»
- колонка 5: SQUARE «Название устройства»
- колонка 6: SQUARE «Способ подключения»
- колонка 7: DIAMOND «Устройство создалось?»; под ним ELLIPSE-круг «Конец» ×2 («не создалось: уходит», «не создалось: пишет в поддержку»)
- колонка 8: SQUARE «Устройство создано»
- колонка 9: ELLIPSE «Флоу «Выдача файла»»

### 3.2. Стрелки (22), «источник → цель: подпись»
1. Флоу «Покупка доступа» → Оплата прошла: «возвращается в приложение»
2. Оплата прошла → Выбор платформы: «подключает устройство» (мимо экрана страны)
3. Главная → Страна: «открывает страну»
4. Страна → ◇Есть свободное место?: «добавляет устройство»
5. Страна → ◇Как заменяет устройство?: «меняет устройство»
6. ◇Есть свободное место? → Выбор платформы: «да: начинает подключение»
7. ◇Есть свободное место? → ◇Что делать с местом?: «нет: места нет»
8. ◇Что делать с местом? → Флоу «Доп. слоты»: «докупает место»
9. ◇Что делать с местом? → Флоу «Удаление устройств»: «освобождает место»
10. ◇Что делать с местом? → Конец: «откладывает»
11. ◇Как заменяет устройство? → Флоу «Удаление устройств»: «удаляет старое, потом создаёт новое»
12. ◇Как заменяет устройство? → Флоу «Перевыпуск конфигурации»: «перевыпускает подключение»
13. Флоу «Удаление устройств» → Страна: «возвращается к стране»
14. Флоу «Перевыпуск конфигурации» → Устройство создано: «получает новое подключение»
15. Выбор платформы → Название устройства: «выбирает своё устройство»
16. Название устройства → Способ подключения: «выбирает имя»
17. Способ подключения → ◇Устройство создалось?: «создаёт устройство»
18. Способ подключения → ◇Устройство создалось? (нижняя дорожка): «выбирает свой способ и создаёт устройство»
19. ◇Устройство создалось? → Устройство создано: «да: получает готовое устройство»
20. ◇Устройство создалось? → Конец: «не создалось: уходит»
21. ◇Устройство создалось? → Конец: «не создалось: пишет в поддержку»
22. Устройство создано → Флоу «Выдача файла»: «переходит к подключению»

Правила нотации: стрелки 17 и 18 входят в ромб слиянием (нижняя дорожка 18 — по образцу v2). Стрелка 13 нарисована только для флоу «Удаление устройств» (в подсценарии автора «удалить старое и создать новое» после удаления нужно создание); возврат из «Доп. слоты» во вводных не описан и не рисуется. ### 10.7. Ответы автора (ЖР §116, версия 5)

1. **Операции в Истории:** только заказы (оплаты) и получение бонусов. Бонусы нужны, чтобы было понятно, что рефералы приносят деньги, по сути это часть реферальной системы (убедиться, что реферальная программа работает и приносит бонусы).

3. **Ссылка на «Реферальную программу» — решение по Ф18/Ф19: овал-ссылка не добавлена.** Оснований, что путь из Истории идёт в реферальный флоу, нет: на старой доске путь «Получение бонуса» (секция 13) идёт через таббар, главную или уведомление, мимо Истории (`research/flow_read_dump.md`); в навигации экранов переходы в реферальный экран идут с «Главной», Профиля (заголовок и статистика) и Навигатора, из Истории — нет (AGENTS.md); во вводных 8059:555, 8062:850, 8057:605 перехода нет. 4. **Предлагаемая правка гипотезы Г6 «чипы месяцев» (для владельца гипотез; сам текст гипотез не менял):** вместо «месяцы берутся только из реальных оплат» — «месяцы берутся только из реальных операций: оплаты и бонусы».
