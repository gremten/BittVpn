# BittVPN implementation contract for future agents

This file is operational documentation. **Read it before changing code.** The Markdown files next to components and screens are not optional notes; they are part of the implementation contract.

## Mandatory documentation workflow

1. Before editing a component, read the adjacent Markdown with the same basename: `Component.js` → `Component.md`.
2. Before editing a screen/page, read the screen Markdown and the Markdown for every reusable component you will touch.
3. Before editing application navigation/state, read `src/App.md` and the relevant screen docs.
4. When adding a new React component or screen, create its same-name `.md` before the task is considered finished.
5. When changing layout, props/API, states, interaction, animation timing, assets, Figma source, navigation behavior, constraints, or known quirks, update the related `.md` **in the same change**.
6. If a change alters a child component in a way that affects a parent screen/flow, update both docs.
7. Do not delete or ignore stale docs to make them “stop disagreeing.” Reconcile the docs with the verified implementation.
8. At the end of work, review `DOCS_INDEX.md` and make sure new/renamed component docs are represented.

## Architecture rules already agreed with the product owner

- This is one CRA/React Telegram Mini App. Main, Locations, Country, CountrySpecifications, Checkout, Profile, Referral, History and HistoryDetail are **DOM/React screen states**, not separate HTML pages and not separate URL routes.
- `src/App.js` owns the internal screen stack. Telegram BackButton must pop that same stack for nested/detail flows.
- Main, Locations and Profile are primary Navigator destinations/root states. Switching among them replaces the root screen and must **not** show Telegram BackButton or turn the host Close control into a Back/app-name control.
- **Telegram BackButton visibility is stack-depth driven.** Depth 1 hides Back; depth >1 shows it. Subscribe the click handler once. Never hide BackButton in a screen-effect cleanup: nested → nested back navigation must leave it continuously visible, otherwise Telegram briefly flips to Close and back.
- Never load production UI assets from temporary **Figma/MCP URLs**. Figma is a design source, not a runtime CDN: export product-owned icons/images into the repo and reference the local files. Approved runtime/user data is different: the Telegram `initDataUnsafe.user.photo_url` profile photo may be loaded remotely.
- Visual warmup is **scheduled before React render but must not start speculative network requests before first paint**. Global App readiness never waits for the visual queue. After first paint, avatar + route UI assets warm in a bounded queue; decorative/pulse/video media waits for idle. Inline SVGR assets are excluded from detached-image warmup.
- Interaction/animation-critical SVGs that must be visible on the very first frame are bundled inline instead of relying only on background warmup. **All Navigator glyph states and the toast success icon are inline React SVG components from local Figma exports.** Do not regress these to `<img>` or runtime Figma/MCP URLs. Static non-critical SVG illustrations may still use local `<img>` when there is no state/animation benefit to inlining.
- Do not rebuild a second/alternative Main. Extend the existing `MainScreen` and existing component system.
- **Locations root (`7435:36711` / `7435:37052`):** common Navigator key `configurations` opens one `LocationsScreen` with shared `Tabs` (`7435:37032`) for `Купленные` / `Доступные`. Reuse the existing `LocationCard` and `NavigatorDock`; do not create screen-local clones. App owns the selected Locations tab so Country → Back restores the same tab.
- Figma is the source of truth for implemented visual geometry. Use exact node measurements/tokens/assets; do not “improve” or approximate the design from memory.
- Working Figma file: `5ks9FYkDbV4fcg60G4SLjf`; working page used for implementation: `🛠️ Userflow и прототипирование`.
- Nodes named with `🔒`, `./`, or `master` are not automatically public components. They are locked/internal design primitives that inform their parent component composition.
- Reuse existing design-system components. Do not create local screen-specific clones of Button, IconButton, LocationCard, Navigator, BottomSheet, etc. just to match one screenshot.
- **Loading surfaces are always skeletons.** If an asynchronous state will resolve into a design-system `Block` (`5943:16932`) or `Card` (`5941:17273`), render that same component with `state="loading"`; never leave the final surface blank and never add a local spinner/shimmer substitute. The canonical skeleton is `bg/loading` at 60% with a 30 px white/20%/37.5 px blurred blinking strip that loops smoothly left → right. Screens may only adjust the skeleton surface height to match their final Figma layout; the blinking treatment stays owned by the base component.
- **Font readiness is skeleton-gated.** Never expose fallback custom-font text and let it visibly swap/reflow. Until the required app fonts are ready, independent text uses the shared `Skeleton type="font"` whose height equals the final line-height; controls use `type="control"` and mirror the base control geometry. If the final surface is Block/Card, keep using `state="loading"` rather than nesting text skeletons inside it.
- **Session media stays warm when repeated navigation would visibly reload it.** Referral matrix rain is one page-session `HTMLVideoElement`: preload once, attach/detach across Referral visits, never clear/reassign its source during navigation.
- **Dot icon morph rule:** device-delete success uses the authored 450ms trash→check transition again. Intermediate motion may use the 12 compact row/column runs, but the final endpoint must be the exact local `icn_el_check.svg` (22 dots). Never use the dashed-line reconstruction as final check artwork; that produced only 17 visible dots on mobile.
- **Global pressed-scale rule:** every component that has scale-based pressed feedback uses `transform: scale(0.985)`. Never introduce per-component values such as `.9`, `.96`, `.98`, or `.995`. Surfaces intentionally specified with **no pressed state** remain without scale; current explicit no-pressed surfaces are the Japan promo banner and the whole `пригласи друга` referral Block. Their nested Button/IconButton controls keep their own `0.985` feedback.
- Chip loading is a canonical blinking skeleton, never a spinner.

Default/active Chip width is intrinsic text width + 24 px horizontal padding; do not add a shared min-width or stretch chips/group to fill. Screen-level horizontal scrolling belongs to a wrapper around the HUG group.

- **BottomSheet layout invariant:** shared `.bottom-sheet` is a flex column. Feature-level `gap` values depend on this; DeviceDeleteSheet data→ButtonGroup is exactly 32px.

- **Bottom action baseline rule:** use `--app-action-safe-bottom = max(32px, var(--app-safe-bottom))` as the shared safe-area floor. CTA physical bottom is `20px + --app-action-safe-bottom`: direct purchase/checkout tabbars include the 20px in their padding; PurchaseDurationSheet/Country renew sheet gets the same 20px from its 76px ButtonGroup. Do not mix raw `--app-safe-bottom` with the 32px-min tabbar floor.

- **BottomSheet layering rule:** shared overlay/surface are z-index 55/56 and must sit above AppTabBar 50. Country purchased renewal must hide its `Продлить доступ` tabbar while `RenewAccessSheet` is open; available purchase hides its PurchaseTabBar while `PurchaseDurationSheet` is open. Never leave a modal sheet behind a tabbar.
- **ContextMenu scrub rule:** Country action-sheet rows reuse `Button type=menu` but have **no scale pressed and no icons**. Pointer-down shows active fill; after 120ms hold (or ≥6px vertical drag) vertical movement transfers that active fill between rows under the finger; release executes the highlighted row. A normal mouse/touch tap must also commit directly on `pointerup` (with the synthetic click suppressed) because pointer capture can prevent reliable click retargeting in Telegram WebView. Horizontal movement ≥14px cancels scrub intent; allow 36px horizontal slop. This mirrors Navigator hold/scrub behavior without its icon/width morph.

- **Telegram black-screen bootstrap rule:** React mounting must not depend on Telegram bridge initialization or optional asset warmup. `index.js` guards Telegram init, mounts React first, then starts warmup. Decorative Sakura session code must use legacy-safe DOM (`appendChild/removeChild`, Promise microtasks) and fail open to the poster; never let optional media throw from layout/effects and take down the root.

- **Dot morph smoothness rule:** current delete trash→check duration is 450ms with key times `0/.22/.76/1` and symmetric cubic `(.45,0,.55,1)`. Keep the exact 22-dot check SVG as the final endpoint. Do not shorten the middle travel phase: the earlier 325ms version still read as abrupt on device.

- **Delete success resize timing:** current Figma `7318:30948` keeps the success action slot at 56px and the data→button gap at 32px. Pending→success only shrinks the title/data by 24px (348→324px at the 34px safe-bottom reference). Keep the 620ms + 40ms delayed `cubic-bezier(.22,1,.36,1)` interpolation; never collapse the success ButtonGroup to 0.

- **ContextMenu hold stability:** ContextMenu owns touch gestures (`touch-action:none`) and suppresses native contextmenu. Do not close it from global scroll events; Telegram/WebViews can emit incidental scroll when a long hold begins, which would cancel the overlay/scrub immediately. Close on outside tap, resize, Escape, or action selection instead.

- **ContextMenu active-fill precedence:** keep `.bitt-context-menu__item.bitt-button.bitt-button--active { background:#242a33; }` after the local transparent ContextMenu base rule. Otherwise React scrub focus changes correctly but CSS hides the active fill.

- **Delete success Figma rule:** source of truth is screen `7318:30920`, concrete BottomSheet `7318:30948`. Success title is `Устройство было удалено`; one enabled 56px Button labeled `Готово` remains visible as `large / secondary / circle / elevated / default` and closes the sheet on tap. At 34px safe bottom the exact sheet height is 324px.

- **Delete success Done button variant:** Figma `7318:30948`, nested instance `I7318:30948;7297:35166;5943:17032` is exactly `size=large, type=secondary, form=circle, color=elevated, state=default`. Never use primary/accent for `Готово`.

- **Prototype device persistence rule:** purchased device counts and per-location deleted device ids are session-only. Main counters derive from the live `sessionStorage` count; Country device lists rebuild from the original template minus session-persisted deleted ids. A fresh app/document session restores the fixture inventory. Never rebuild from only `deviceCount`, because deleting a middle device would resurrect/reorder devices on Country re-entry.
